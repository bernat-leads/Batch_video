# Database Reference — SOP

> Procedures for working with the PostgreSQL database. Migrations are always autogenerated.

---

## Overview

| Property | Value |
|----------|-------|
| Database | PostgreSQL |
| ORM | SQLAlchemy 2.0 (async) |
| Migration tool | Alembic (autogenerate only) |
| Config | `apps/api/alembic.ini` |
| Models | `apps/api/api/*/models/` |
| Port (local) | 5433 |

---

## Tables

| Table | Module | Purpose |
|-------|--------|---------|
| `videos` | `videos/` | Video records: script, prompt, status, stage, costs, output |
| `shots` | `videos/` | Per-video segments: text, image prompt, Ken Burns config, timing |
| `batches` | `videos/` | Batch groupings: name, aggregated costs (no status column) |
| `app_settings` | `settings_module/` | Singleton: master_prompt, retention_days |

## Enums (stored as VARCHAR, validated in Python)

| Enum | Values | Used In |
|------|--------|---------|
| `VideoStatus` | `pending`, `processing`, `completed`, `failed` | `videos.status` |
| `VideoStage` | `queued`, `tts`, `segmentation`, `image_generation`, `assembly`, `upload`, `done` | `videos.current_stage` |

## Key Relationships

- `videos.batch_id` → `batches.id` (CASCADE delete, nullable, indexed)
- `shots.video_id` → `videos.id` (CASCADE delete, indexed)
- Batch status is **derived** from video counts (no DB column)

## Base Model

All models inherit `created_at` and `updated_at` from `BaseModel` (UTC, no timezone):
```python
class BaseModel(DeclarativeBase):
    __abstract__ = True
    created_at: Mapped[datetime]  # auto UTC
    updated_at: Mapped[datetime | None]  # auto UTC on update
```

## SOP: Add a New Table

1. Create SQLAlchemy model in `api/{module}/models/`:
   ```python
   class MyModel(BaseModel):
       __tablename__ = "my_table"
       id: Mapped[uuid.UUID] = mapped_column(UUID(as_uuid=True), primary_key=True, default=uuid.uuid4)
       name: Mapped[str] = mapped_column(String(255), nullable=False)
   ```
2. Export in `models/__init__.py`
3. Import in `migrations/env.py`
4. Generate migration:
   ```bash
   cd apps/api && poetry run alembic revision --autogenerate -m "add my_table"
   ```
5. Review the generated migration file
6. Apply: `poetry run alembic upgrade head`

## SOP: Add a Column to Existing Table

1. Add column to SQLAlchemy model
2. Generate migration:
   ```bash
   cd apps/api && poetry run alembic revision --autogenerate -m "add column_name to table_name"
   ```
3. **If NOT NULL without default:** Edit migration to add `server_default`:
   ```python
   op.add_column('table', sa.Column('col', sa.Text(), server_default='', nullable=False))
   ```
4. Apply: `poetry run alembic upgrade head`
5. Regenerate client: `pnpm run generate-api`

## SOP: Add an Enum Type

1. Define in `api/{module}/enums.py`:
   ```python
   class MyStatus(str, enum.Enum):
       active = "active"
       archived = "archived"
   ```
2. Use in model: `Mapped[MyStatus] = mapped_column(String(20), default=MyStatus.active)`
3. Use in schemas: `status: MyStatus`
4. Use in queries: `Model.status == MyStatus.active`
5. Orval generates TS const enum on `pnpm run generate-api`

## SOP: Run Migrations

```bash
cd apps/api
poetry run alembic upgrade head          # Apply all pending
poetry run alembic downgrade -1           # Rollback last
poetry run alembic current                # Show current revision
poetry run alembic history                # Show migration history
```

## Rules

- **NEVER** hand-write migration files — always `alembic revision --autogenerate`
- **NEVER** use raw SQL strings for status comparisons — use enum constants
- UUID primary keys, snake_case table/column names
- Index foreign keys and frequently-filtered columns
- Timestamps inherited from BaseModel (never define manually)
